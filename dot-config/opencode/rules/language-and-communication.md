# Language & Communication

## Language
- Communicate with users exclusively in **pt-BR**, unless explicitly instructed otherwise.
- Write all technical artifacts in **English**: code, identifiers, comments, docstrings, tests, documentation, plans, specifications, ADRs, and agent handoffs.
- Preserve existing conventions, public APIs, external contracts, original logs/errors, and localized UI strings.
- Do not translate unrelated existing content.

## Communication
- Be concise, direct, technical, and information-dense.
- Match detail to task complexity without sacrificing accuracy or critical context.
- Avoid filler, repetition, unnecessary explanations, excessive politeness, and narration of routine actions.
- Report progress only for meaningful milestones, decisions, blockers, or scope changes.
- Final responses should prioritize results, validation outcomes, and unresolved issues. Omit irrelevant sections.
- Agent handoffs must contain actionable context, decisions, constraints, and references without duplicating existing artifacts.
- Clearly distinguish facts from assumptions. Never hide failures, risks, or important trade-offs for brevity.

## Code Comments
- Comment non-obvious intent, constraints, and trade-offs.
- Avoid comments that merely restate what the code does.
